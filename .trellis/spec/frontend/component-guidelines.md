# Component Guidelines

> Executable component and accessibility conventions for xi-ai-web.

## Component Structure

- Use typed React function components. Keep feature-local state and helpers in the owning feature module unless a behavior is reused by at least two modules.
- `src/App.tsx` owns public bootstrap state, the active public module, BYOK state, the API modal, and shared gallery items.
- Shared public shell components live in `src/app/`; shared workbench composition lives in `src/components/workbench/`; reusable interaction primitives live in `src/components/ui/`.
- Preserve lazy module boundaries. Tests must wait for the module body, not only the shell title.
- Public menu changes animate only `.figma-workspace-canvas`: keep the current module mounted during import, use a cancellable short exit phase followed by a short new-canvas entry phase, and leave navigation, shell geometry, footer, and scroll-owner dimensions unchanged. Cancel the phase timer on a newer request, bootstrap refresh, import failure, and unmount; History API restoration and `prefers-reduced-motion: reduce` commit the destination immediately without practical motion.
- Public module navigation uses `src/app/publicModuleLoader.ts` as the shared lazy-import cache. Enabled menu items preload their destination from pointer and keyboard intent, while a conservative idle preload warms only the most likely next module and skips save-data / 2G connections.
- `PublicBootstrapPayload.menuItems[].label` is the authoritative runtime label for public navigation text and accessible names, document titles, and module-transition status/error copy. Resolve it through `cleanMenuLabel(moduleId, item.label)` so `navigationMeta` and `moduleMeta` remain fallback metadata only; never render a static registry label over an Admin-managed value. Browser coverage must inject a non-default menu label and assert it on both desktop and mobile navigation plus the destination document title.
- A cold public-module switch must retain the current module until the destination import resolves. Show the compact `.figma-module-transition` progress treatment without moving shell geometry, then animate only the new canvas. Failed imports preserve the current module, restore its canonical URL, and expose an accessible clean-document retry. Respect `prefers-reduced-motion` for the canvas, progress, spinner, and pending navigation icon.
- When `activeModule` commits, `AppShell` resets the shared `.figma-workspace` horizontal and vertical scroll offsets in a layout effect. Never reset from `pendingModule` or a lazy child: pending and failed imports must preserve the current module's scroll position, while every completed public destination opens at its top edge.

## Overlay Contract

Use `src/components/ui/Dialog.tsx` for modals, sheets, and side inspectors. Use `ConfirmationDialog` for destructive confirmation.

Every shared dialog must provide:

- `role="dialog"` for ordinary overlays or `role="alertdialog"` for destructive confirmation, plus `aria-modal="true"` and a stable `labelledBy` target.
- Initial focus, Tab trapping, allowed Escape/scrim behavior, and trigger focus restoration.
- `#root` inertness and body scroll locking while open.
- `data-scroll-owner="dialog"` on the dialog itself. Background scroll-owner attributes are suspended for the overlay lifetime, including owners mounted later by lazy content.
- A maximum `16px` radius. Backdrop blur is allowed only on the scrim while `.figma-session-settings` or `.figma-agent-dialog` is open, matching the authoritative Figma overlays.
- When one dialog temporarily replaces another, keep only one open and pass the original trigger through `returnFocusRef`; do not let the replacement dialog become the final focus-restoration target.

The desktop cross-device sync dialog uses a stable `480px x min(440px, 100dvh - 32px)` shell with a fixed header and one `minmax(0, 1fr)` body. Direction and receive-method switches must preserve the dialog, header, tabs, body, and panel bounding boxes within `1px`; animate only panel opacity/translation, never dialog geometry. Fixed QR-stage contents must not use a transform during entry animation because the transformed bounding box can extend beyond the stage while the animation is running; use opacity-only entry for approval content. Sender and receiver idle views share instruction, secondary-option, and primary-action slots. Long QR, fingerprint, preview, error, and completion states overflow only through `.progress-sync-dialog-body`; its native scrollbar track, thumb, and buttons stay transparent until that body receives a real scroll event, then return to transparent after the debounce window. Preview count cards must not create a nested scroll owner. When a desktop QR sender enters approval, the approval state replaces the QR stage in place and keeps Confirm and Send visible before any body scroll; move focus to that button once without activating it. Mobile and manual-code approval stays the first session item when no QR stage exists. Below `1024px`, remove the fixed desktop height, retain the visual-viewport/safe-area cap, and keep one visible dialog scroll owner.

The required first-use API dialog passes `canClose={false}` until the existing provider readiness rule is satisfied. Once ready, the desktop access card and mobile function menu may reopen that same dialog through a masked session-Key replacement row. The desktop card uses one header plus a two-row connection-details group: a static service-address row and an interactive Key row share the same icon/text grid and internal divider; do not restore scattered endpoint text or a repeated encrypted-status footer. Shell children receive only the masked label and open callback; they never receive the full Key. Do not add a second editor or close path.

The public workspace-data dialog is separate from the required BYOK dialog. Its desktop/mobile trigger is an icon action outside the eight destination buttons. During destructive replace confirmation, hide the workspace-data dialog so exactly one visible dialog and one `data-scroll-owner="dialog"` remain.

Browser-local automation pages live under `src/features/automation/`. Agents and workflows are public pages; Skills remain browser-local records consumed from Chat. Session Settings temporarily exposes no Skill category, selection list, or manager entry; `$` still selects compatible stored Skills for the current conversation. Keep executable code out of Skill definitions, send resolved Skill text only through the user-initiated Chat request, and use the restricted Start/Agent/Text Template/Local Knowledge Retrieval/Reply graph canvas for workflows. Workflows open from a saved-card catalog into a single full-width detail editor; do not restore a permanently mounted workflow list beside the canvas.

Agents use the same two-level information architecture: a searchable/category-filtered card catalog first, then one dedicated editor and test runner. Cards summarize model, Skill, tool, local-knowledge, and update metadata. The editor may bind IndexedDB knowledge documents, but request text/chunks are resolved only at run time and never copied into the saved Agent definition.

The public Assistant library renders the actual enabled bootstrap records. Category, tags, and starter prompts come from the `Assistant` contract; do not restore hard-coded decorative profiles or index-based mapping to unrelated assistant IDs. Starter prompts are selectable visible drafts and never auto-send. Chat shows the assistant bound to each conversation on desktop and mobile.

Admin uses a controlled two-level information architecture. First-level sidebar groups are real buttons with `aria-expanded` and `aria-controls`; second-level destinations share one typed `AdminSectionId` source with the grouped mobile select. Mount only the active destination section so operations, model, assistant, application, prompt, and audit forms are not all present in the document. Keep form drafts in `AdminConsole` so destination switches do not discard unsaved input.

All Admin destinations share the same `.admin-console-inner` content boundary: fill the available Admin content track up to `1680px`, use responsive horizontal padding, and keep exactly one active `.admin-section`. Do not restore destination-specific `:has()` width exceptions or a global `980px` bottleneck. Low-density settings should use internal form grids rather than narrowing the entire destination; data grids and operational pages may use the full shared track. Wide-desktop E2E must traverse every `AdminSectionId` and assert both document and `.admin-console` horizontal containment.

Desktop Admin navigation uses a 288px rail. An expanded group is one surface whose first-level button and single-column destination cards share the same left boundary. Do not indent second-level destinations outside that surface, add selection shadows, or change tile geometry between idle, hover, and active states. Below 760px the shared grouped select remains the only navigation source.

The Admin model catalog uses three ownership columns: vendor rail, current-vendor model list, and model inspector. Vendor and model columns share one three-part frame: heading, bounded internal scroller, and bottom management area. Both row types support direct drag ordering on desktop plus explicit move controls on touch layouts. Moving a model reorders only the active vendor's projection, then persists the resulting complete global model-ID order through the atomic endpoint so public defaults remain deterministic. Model creation and guarded deletion live in the model-column footer; the inspector owns editing and saving only. Configured models, unsaved drafts, and available presets share the bounded model scroller, while presets never participate in configured-model ordering. Both scrollers reserve a stable 7px scrollbar gutter, keep the thumb transparent while idle, and reveal a low-contrast thumb only during their own debounced scroll-active state. The inspector does not repeat the vendor selector or display/request mapping preview: model ownership comes from the active vendor route and remains in the parent draft/payload. Activate a created vendor from the returned `ModelVendorEntry.id`, never by matching the submitted label or adapter. When imported/restored bootstrap data removes the active selection, retain a still-valid model, otherwise select the first model, or create an unsaved draft under the first surviving vendor when the catalog is empty.

On desktop widths above `1100px`, the model destination fills the remaining Admin viewport and disables outer `.admin-console` scrolling. The workbench, both list footers, and the inspector save action must remain inside the viewport at `1280x800`, `1440x900`, and `2048x955`; vendor/model overflow stays inside their existing scrollers, while unusually long inspector content may scroll only inside the inspector. Mobile retains the normal document flow and its existing single visible scroll owner. Model capabilities use independent `aria-pressed` toggle buttons with compact rounded corners and wrap-to-content labels; never force them into equal-width columns or ellipsize a capability name. `streaming` is not a model capability: legacy catalog/import values are stripped during normalization and the Admin inspector never exposes it.

Knowledge operations are one Admin navigation group with exactly six destinations: overview, accounts, registration/invites, limits, jobs/storage, and knowledge audit. `KnowledgeAdminSection` mounts only the selected destination, uses the shared Admin confirmation flow for destructive account actions, and never renders secrets from list/read payloads. Newly issued invite/reset plaintext is a live, one-time callout; navigating away intentionally destroys that value rather than moving it into `AdminConsole`, browser storage, or a toast history.

The jobs/storage destination keeps one transient operation-reason field. Failed/cancelled jobs expose Retry; queued/running/retry jobs expose Cancel through the shared destructive confirmation dialog. Replace the matching `KnowledgeAdminJob` projection in memory after success, and never surface lease-owner or raw error-detail fields. Job rows must remain single-column on mobile and must not create document overflow when action buttons appear.

The Chat composer uses `$` for Skill commands and `/` for enabled application commands. Keep keyboard focus in the textarea while the listbox is visible, use Arrow keys/Enter/Escape plus touchable option buttons, and render selected items as removable composer tags rather than visible command syntax.

Pending Chat attachments render in one compact, horizontally scrollable tray immediately before `.figma-composer`, never inside it. Keep image thumbnails and text-file icons bounded so attachments do not reduce the message-entry area; the configured image limit counts images only and individual removal stays available from each item.

Chat message Markdown uses `remark-gfm` plus `remark-math` and `rehype-katex`; keep raw HTML disabled. Fenced code is rendered through the Chat-owned code block component with a language label, copy action, horizontal overflow, and a Clipboard API fallback for HTTP deployments. Do not execute or syntax-evaluate message code.

Chat Session Settings use `ChatSessionSettingsDialog` for presentation and `chatSessionSettings.ts` as the typed default/sanitization/sessionStorage boundary. Keep the saved settings object separate from the dialog draft so Cancel is structural rather than a live-state rollback. The dialog uses seven category tabs with one visible panel: a persistent left category menu on desktop and a horizontally scrollable category row on mobile. Category rows reuse the public shell navigation language: bare icons, transparent inactive rows, a full primary-fill active row, 16px desktop radius, and the same title/helper hierarchy; do not introduce a second icon-tile or inset-accent pattern. Keep the shared dialog as the only vertical scroll owner, reset to Appearance on open, and preserve `tablist` / `tab` / `tabpanel` semantics with keyboard navigation. Category changes must keep the dialog's viewport-relative geometry stable and reset its internal scroll position without browser scroll anchoring. Settings must have an active behavior; omit screenshot-inspired controls that would be inert or unsafe. HTML code preview is permitted only in an empty-sandbox iframe with a restrictive inline CSP and no raw HTML path in the message document.

Chat message typography has one setting-owned size across every viewport. `defaultChatSessionSettings.messageFontSize` and the CSS fallback are `13px`; persisted valid `13-18px` choices remain unchanged. Responsive rules must consume `var(--figma-message-font-size)` rather than replace it with a fixed mobile size. Dark typography uses the screen-optimized dark `--font-ui` / `--font-mono` stacks with native `font-smoothing: auto`; improve small-text clarity through readable text tokens rather than parent opacity, filters, text shadows, or global synthetic bolding.

The expanded Chat session controls are the stacking owner for composer toolbar menus. Keep `.figma-session-controls` positioned above `.figma-message-history` with an opaque surface so upward-opening mobile menus remain clickable instead of being intercepted by the scroll layer.

An empty Chat conversation renders exactly one ephemeral Assistant welcome message. Do not add sample user questions or sample Assistant answers to the empty-state message list, and do not persist the welcome message into the conversation record.

Model Settings keep the model context window as a discrete slider, plus a default-off maximum-output switch with a compact manual value field and the shared confirmation dialog before enabling that limit. Referenced-history count belongs in the expanded conversation's composer toolbar as one `FigmaMenu`; it applies and persists immediately, while Session Settings must not duplicate it. Token usage belongs beside that menu: show the latest provider-reported input/output/total values when available and an explicitly labelled estimate of the selected context otherwise. It is plain text with no icon, fill, border, padding, radius, or per-message copy. Tool invocation is one right-side `FigmaMenu`, not a full-width segmented selector. `streamOutput` belongs only to Chat Session Settings and controls whether Chat applies token events incrementally; generation modules and model capability filters must not read it. SSE transport and message `status: "streaming"` remain runtime concerns rather than catalog metadata.

Chat session cards keep browser-local pin state. Exactly one conversation may be expanded: expanding another conversation collapses every previously expanded card, moves the new active card to the top, and returns the collapsed cards to pin-first then persisted-`updatedAt` ordering. A pinned collapsed card can never cover an active composer. Explicit or automatic collapse of a changed non-streaming conversation may request a fresh title through the current BYOK connection; use the configured enabled chat model and recent-message count, persist `titleSummaryAt`, and never trigger bulk title calls during hydration.

Chat assistant and personal avatar presets share the typed catalog in `chatSessionSettings.ts` but persist independent IDs. Project avatar assets are square PNGs with transparent corners and circular subject framing. A session-only custom personal-avatar data URL overrides the preset visually without erasing the preset selection.

Chat tool invocation has exactly two modes: Prompt and Function Calling. Function Calling uses the existing provider-native adapters. Prompt mode may expose server-owned local tool schemas through the strict JSON protocol in `server/tools/prompt-runner.mjs`; it must still resolve names through the server allowlist, validate arguments, bound results and rounds, and reject provider-hosted tools.

Chat message rows are Grid children that also act as Flex containers. Keep `.figma-message { width: 100%; min-width: 0; }` and bound `.figma-code-block` to `width/max-width: 100%`; long code must increase the nested `pre.scrollWidth`, never the message track width. Mobile browser coverage must assert that the Copy Code control remains inside the viewport while the code body scrolls horizontally.

Tool-bearing Skills are available through Chat's `$` command list when the selected model and server catalog are compatible. Disabled command rows show the specific model, vendor, admin, connection, or context reason. Chat's network-search control requests `web_search`, checks administrator enablement plus BYOK readiness, and never depends on the selected main model's `webSearch` or `toolCalling` capability. It opens one vertical GLM/Kimi/Off provider menu and derives the search request from the active user API Key plus the administrator-managed upstream; do not restore a settings icon or `SearchServiceDialog` in Chat. Skill and Agent tool pickers distinguish local execution, independent search, and provider-hosted execution; Admin presents the same ownership boundary.

Native Chat token events are accumulated in a per-stream memory snapshot, rendered at most once per `requestAnimationFrame`, and persisted no more often than the bounded 300ms streaming interval. `done`, `error`, stop, unmount, and stream replacement flush or settle the exact final message; a token handler must not call `commitConversations` or IndexedDB once per provider fragment. This client cadence complements the server SSE micro-buffer and must not add an artificial per-character delay.

Controlled React Flow nodes must declare stable card dimensions so edge routing, fit bounds, and MiniMap nodes share the same geometry. Keep the default viewport readable, expose a compact colored MiniMap plus an explicit fit control, and do not automatically shrink a multi-node graph until labels become unreadable. Browser tests must assert both the MiniMap node count and the fit-control result.

Local workflow components use `src/features/automation/workflowComponents.ts` as the single source of truth for IDs, versions, labels, ports, configuration fields, executors, capability requirements, and security levels. Legacy nodes may be projected by `kind`, but new records and imported Langflow nodes must carry the stable component ID and version. `workflowLangflowImport.ts` may translate declarative topology and bounded configuration only; arbitrary Python, JavaScript, shell, SQL, filesystem, credential, and provider-binding fields become visible blocked nodes or warnings and must never become executable browser code. Unsupported nodes remain in the graph so users can inspect and repair the import, and graph validation must fail before any provider request. Execution state types live in an automation contract module rather than importing the React Flow presentation component into the scheduler.

Browser-generated identifiers use `src/utils/clientId.ts`. Do not call `crypto.randomUUID()` directly in frontend modules because HTTP IP deployments are not secure contexts and may expose only `crypto.getRandomValues()`.

Assistant avatars use the local semantic catalog in `src/features/assistants/assistantAvatars.ts` and render through `AssistantAvatar`. Cards, details, Admin previews, collapsed sessions, and assistant messages consume the same allowlisted key; do not load runtime Iconfont/CDN scripts or map arbitrary remote avatar URLs. The session-level legacy avatar preset remains the fallback for assistants without a valid semantic key.

## Props And Composition

- Define component props with named `type` declarations and use domain types from `src/types.ts` for shared contracts.
- Pass commands as callbacks; do not make presentation components import root state or persistence helpers.
- Prefer one functional panel with internal dividers. Do not place cards inside cards solely to create depth.
- Use Lucide icons already installed in the project. Icon-only controls require an accessible name and `title`.

## Large Feature Composition

- A route-facing feature coordinator may own loading, persistence, and cross-section callbacks, but it must not keep every independent workspace in one file.
- Studio uses `StudioModule.tsx` only as a `moduleId` switch. `studioShared.tsx` owns `StudioModuleProps`, `useStudioModel`, and `StudioModelSelect`; each five-page workspace owns its own JSX and request projection.
- PPT Studio keeps UI-facing recommendations in `pptPresets.ts`: changing the presentation type explicitly applies its audience, duration, page-count, narrative, density, tone, and theme defaults, while the resulting field state remains editable and is the only request source. Trusted preset instructions stay in `server/ppt-preset-profiles.mjs`; never send a browser-authored system prompt. Desktop keeps an approximately `296px` settings track and `152px` thumbnail rail, then stacks below `1100px`. When preset or preview logic moves into another file, add that file to every static `studioModule` concatenation rather than weakening the contract assertion.
- Mind Map Studio uses `MindmapDocument` as the authoritative edited state. `mindmapDocument.ts` owns unknown-result normalization, immutable rename/note/add/delete/sibling-move operations, and Markdown/Mermaid serialization; `MindmapTreeCanvas` owns deterministic bilateral layout, selection, collapse state, zoom, fit, and internal scrolling. Local edits, collapse, and zoom never call the Provider. AI Expand sends the selected node ID plus the bounded current document and must preserve unrelated branches; AI Reorganize sends and replaces the complete bounded document. Source editing and Markdown, Mermaid, SVG, PNG, and clipboard exports must all reflect the current edited document. Do not restore the four decorative branch cards, fake local AI actions, free node dragging, or cross-node relationship edges.
- Image Studio keeps generation controls inside the prompt card's bottom control deck. The visible parameter contract is exactly model, unified size, and quality; every public Image Studio request uses `count: 1`, and the quantity menu must not return. Size projects `1K|2K|4K` plus square/landscape/portrait into provider-facing resolution, aspect ratio, and pixel size; unsupported high resolutions fall back to `1K` while retaining orientation. PNG, automatic background, no PNG compression, and one-image count remain internal request defaults. Desktop uses a stable split workbench with the form on the left and one persistent idle/loading/result pane on the right; below 1024px it stacks form then result without overflow. ETA comes from `/api/image/timing-estimate` and the successful generation response, uses at most the latest 10 server-global successful samples, and renders with elapsed time inside the aspect-ratio-aware result frame. Loading uses the scoped rotating border indicator and respects reduced motion; do not restore the former ETA pill, progress rail, browser IndexedDB timing reads/writes, or a sticky parameter rail.
- Image generation results use `ImageResultGallery` as a compact thumbnail grid and open the shared `Dialog` for inspection. Rotation and horizontal/vertical flips must affect copied, downloaded, and edit-handoff PNG bytes; zoom remains preview-only. Regenerate must call the owning form's existing submit path, and edit handoff must select a local-input-capable image-edit model before filling the source image. Browser-readable assets transform locally; CORS-blocked HTTPS assets retry through `/api/image/import`, which must validate a public non-credentialed URL, reject redirects/private DNS targets/non-image bytes, and enforce the shared 20 MB edit limit plus a bounded timeout. Defer `scrollIntoView` until after the preview closes so dialog scroll locking cannot swallow the editor navigation. Keep one dialog scroll owner, rotation-aware containment for non-square images, 44px mobile controls, image-clipboard copy with URL fallback, and explicit download/copy CORS feedback rather than restoring full-width result images or duplicating Provider requests.
- Automation uses `AutomationModule.tsx` only for browser-workspace hydration and save callbacks. `AgentsWorkspace.tsx` and `WorkflowsWorkspace.tsx` own their catalog/editor/runner flows; shared cards and execution types live in `automationShared.tsx`.
- Admin keeps draft state and confirmation actions in `AdminConsole.tsx`, while each destination section receives typed values and callbacks. Mount only the active section.
- When a feature is split, update every static contract reader to concatenate the coordinator and extracted files. Never weaken a contract merely because a symbol moved.

## Styling

- Global CSS is imported through `src/styles.css`; import order is a compatibility contract.
- The `rednote-flat-v2.*.css` files are the authoritative active layer. Extend the module-owned file instead of adding a trailing override sheet.
- Module dialogs that override base `.ui-dialog` geometry must use a compound selector such as `.ui-dialog.<module-dialog>`. The shared modal stylesheet loads after feature styles, so an equal-specificity single class can silently lose its width or overflow contract.
- Public workspaces use the exact Figma Make tokens: light `#f5f8ff / #10203d / #2368e8`, dark `#080c14 / #0f1623 / #4f8dff`, `16px` radii, and quiet blue-gray borders.
- Active UI metadata never renders below `10px`. Use the shared `--font-ui` / `--font-mono` stacks so Chinese text reaches `PingFang SC` or `Microsoft YaHei UI` before a generic sans-serif or monospace fallback.
- Active v2 form controls neutralize legacy gradients and inset highlights. Use one continuous border and one box-shadow-based focus ring; do not stack browser outlines, white top-edge highlights, or multiple focus shadows in dark mode.
- Text-bearing filled primary surfaces use `--xhs-primary-fill` with `--xhs-on-primary`; reserve the brighter dark `--xhs-red` token for links, focus, progress, and icon accents where the contrast contract differs.
- Styled range controls must explicitly reset the legacy global input border, padding, minimum height, background, and box shadow. Keep the visual track/progress separate from the mobile hit area so desktop remains compact and mobile still provides a `44px` target.
- At the acceptance desktop viewports, `.figma-studio-shell` reserves a fixed `224px` `.figma-sidebar`; the workspace owns the remaining `minmax(0, 1fr)` track.
- Below `1024px`, `.figma-mobile-header` replaces the desktop rail and `.figma-sidebar.mobile-open` becomes a single vertical function menu. There is no top module strip or bottom navigation.
- At `1024px` and above, keep the authored `224px` rail and `32px` shell gap; do not reintroduce the retired tablet compression rule.
- Shared authored parameter menus use `FigmaMenu` with a `16px` trigger/popover radius, visible selected state, outside-pointer dismissal, Escape dismissal, and trigger focus restoration. Keep `placement="auto"` as the shared default. Image Studio is the scoped exception: its four equal-width parameter menus explicitly use `placement="up"`, their popovers match the trigger width, and they share the same reduced-motion-aware fade/translate entrance animation. Do not force placement for other consumers without a destination-specific requirement.
- Studio generation pages use the shared `StudioModelSelect` projection over the developer-managed catalog. PPT, Mind Map, and Translation filter enabled `chat`-capable models, expose page-specific accessible names plus current-value descriptions, lock selection during in-flight generation, and pass the selected model ID through the existing request rather than introducing module-specific model capabilities.
- Model catalog entries keep `contextWindowTokens` and `maxInputCharacters` as independent administrator-editable values. Translation uses `maxInputCharacters` exactly, labels the counter as characters rather than Tokens, and updates `maxLength` when model selection changes; it must not derive, convert, or reserve characters from the context window. Legacy catalog entries receive a normalized character-limit default instead of falling back to a fixed 5,000-character limit.
- Admin model capabilities use one compact labelled checkbox grid without helper copy or table dividers. Use eight columns on wide screens, five at 1440-class widths, three at 1280-class widths, and responsive 3/2-column mobile layouts; labels must remain fully readable. Current-vendor model rows own default priority directly: desktop exposes a drag handle plus explicit move buttons, while mobile hides pointer drag and retains 44px move controls. Do not emit success toasts or position announcements after a move; save failure remains visible inline. The first enabled compatible model in the persisted global order remains the public default, and no competing default-purpose selector may be restored.
- Scrollable model lists reserve a stable scrollbar gutter. When the product calls for an auto-hiding scrollbar, keep the scrollbar width constant and change only its visual color during a debounced scroll state; toggling `overflow`, scrollbar width, or `display` causes row-width jitter.
- Nested content scrollers inside the public workspace must release vertical wheel input to `.figma-workspace` at their boundaries. Do not use `overscroll-behavior-y: contain` on Chat message history; dialog-owned scrollers remain isolated by the shared overlay contract.
- Chat message history keeps the standard scrollbar color transparent while idle and hovered. Its own `scroll` event sets `data-scroll-active="true"` for the existing 650ms debounce; do not add a hover selector, a WebKit scrollbar width override, or a stable gutter because those either reveal on pointer entry or reduce the authored 1024px message track on Windows Chromium. Streaming bottom-follow must depend on the latest message content and set the history element's `scrollTop` to its `scrollHeight` in a layout effect. Do not restore a bottom sentinel with `scrollIntoView`, which misses same-message token growth and may move the outer workspace.
- Chat's vendor tablist and model list own independent debounced scroll-active states. Both reserve `scrollbar-gutter: stable`, keep a fixed `4px` WebKit width, and reveal only a semi-transparent tokenized thumb (`0.42` light / `0.46` dark); scrolling one column must not reveal or resize the other.
- The selected Chat model vendor uses a borderless `10px` pill with a `16%` red-to-surface background mix and at least `700` font weight. Inactive vendors remain transparent and hover uses only a `5%` tint so selection is always the strongest state without changing tab dimensions.
- Chat's custom vendor/model list groups options with `4px` grid gaps and local `10px` row radii. Model rows have no divider border and rest on a transparent background; hover/focus and selected fills provide separation without a table-like surface. Preserve the `46px` row height and verify computed `border-bottom-width: 0px`, radius, gap, popover geometry, and scrollbar widths in browser tests.
- The public shell switches to mobile navigation below `1024px`; controls introduced into that shell range must keep at least `44px` touch height even when their full stacked mobile composition begins at a narrower breakpoint.
- Hero emphasis phrases stay as inline text with `white-space: nowrap`; using `display: inline-block` inserts a separator in the accessibility tree and changes exact heading names.
- Approved gradients are limited to `.figma-brand-mark`, the authored `.figma-ppt-stages` creation panel, and the dotted `.figma-map-canvas` pattern. Do not add other page gradients, persistent glass blur, decorative glow, negative letter spacing, or viewport-scaled font sizes.
- The first-use BYOK dialog contains only the Figma-style heading, API Key, key visibility control, and save command. Do not restore an external URL field, provider presets, summaries, readiness cards, reset actions, or a generic public API-settings button. A pending Shell type-3 handoff temporarily replaces this dialog with the boot state; failure returns to this same dialog. The only persistent shell credential action is the scoped masked session-Key replacement row in the desktop access card and mobile function menu.
- An expanded desktop `.figma-chat-session` is a viewport-bounded three-row grid: header, `minmax(0, 1fr)` message history, and controls. The history owns the remaining height and scrolls internally; the composer and generation note stay at least `12px` above the viewport bottom at the accepted desktop sizes. Below `1024px`, remove the fixed session height, keep natural public-workspace flow, and add `env(safe-area-inset-bottom)` to the controls padding.

## Accessibility

- Mobile targets are at least `44x44px`; desktop icon controls are at least `36x36px`.
- Use the full accessible name even when the visible mobile label is shortened. Example: visible `导图`, `aria-label="思维导图"`.
- Filters use `aria-pressed`; segmented views use tab semantics only when they switch real views.
- Destructive batch/admin actions require confirmation. A single local delete may use immediate deletion only when Undo is guaranteed.
- Every mobile screen exposes exactly one visible `[data-scroll-owner]`; an open overlay becomes the sole owner.

## Common Mistakes

- Hand-rolling another focus trap instead of using `Dialog`.
- Mutating a parent scroll-owner from a lazy child effect. The shell route state must declare the owner synchronously.
