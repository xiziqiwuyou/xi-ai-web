# v0.0.7 运营上线审计与发布

## Goal

以 `v0.0.6` 和提交 `81e42ef` 为代码基线，完成一次面向真实运营的发布审计。依据代码、自动化测试、部署配置和可复现运行证据，将功能划分为“正式开放、Beta 开放、默认隐藏”，只修复阻止核心业务上线的 P0/P1 问题，最终发布可回滚的 `v0.0.7`。

## Confirmed Facts

- 当前 `package.json` 版本为 `0.0.6`，最新提交为 `81e42ef feat: add OneAPI settings handoff`。
- OneAPI settings 入口默认关闭，Shell type-3 JWT、OneAPI direct-Key 和手动 BYOK 已保持独立。
- 当前工作区有未提交的同步弹窗 CSS/E2E，以及未跟踪的监督智能体和旧版本规划资料；发布前必须逐项判定，禁止无差别提交。
- 历史 Trellis 中存在大量 `in_progress` 任务，状态不可作为功能完成度证据。
- `v0.0.6` 的 Chat/Image 上线验收计划仍未形成真实 API 证据，因此合同测试通过不能被描述成真实厂商调用已验证。

## Requirements

### R1. 发布边界与证据

- 生成一份功能矩阵，逐项记录用户入口、核心链路、持久化边界、依赖、测试证据、风险和开放级别。
- 正式开放必须具备完整主流程、可恢复错误、隐私边界、桌面/移动端关键测试和部署健康检查。
- 依赖额外服务或缺少真实联调证据的功能只能标记 Beta 或默认关闭；仅有 UI 的功能必须隐藏。
- 自动化证据、真实 API 联调、线上检查必须分开记录，不得相互替代。

### R2. 核心上线范围

- 审计 AI 对话、图片生成、手动 BYOK、模型目录与端点路由、流式 SSE、图片字节交付、管理员配置和 Docker 部署。
- 审计 Shell type-3 JWT 和 OneAPI settings 安全隔离；外部 URL 不得覆盖管理员上游地址。
- 审计 API Key、令牌、知识文档和同步数据是否可能进入日志、localStorage、IndexedDB、导出或服务端元数据。

### R3. 次级功能分级

- 对智能体、助手库、工作流、PPT、思维导图、翻译、知识库、跨设备同步分别判定正式、Beta 或隐藏。
- 不因页面存在而判定功能完整；需要检查请求、保存、恢复、权限、失败和依赖配置。

### R4. 修复限制

- 只修复有明确证据的 P0/P1 发布阻塞项。
- 不进行大型组件拆分、全局 CSS 清理、数据库迁移或整套 UI 重构。
- 不新增供应商协议、公共账号系统、第三方依赖或任意上游 URL。

### R5. 版本发布

- 发布目标版本为 `v0.0.7`，不得覆盖 `v0.0.6`。
- 发布提交只包含经审查且有验证证据的代码、测试、规范和部署资料。
- 更新版本号、发布说明、Compose 镜像标签，并在验证通过后推送 GitHub、创建 `v0.0.7` 标签和确认 GHCR 构建。
- 输出服务器升级、健康检查和回滚命令。

## Out of Scope

- 不使用真实用户长期 Key 作为自动化测试数据。
- 不伪造第三方 API、GitHub Actions、GHCR 或线上服务成功状态。
- 不清理或批量归档全部历史 Trellis 任务。
- 不继续开发新的产品功能。

## Acceptance Criteria

- [ ] 形成完整功能开放矩阵及对应证据。
- [ ] 所有 P0/P1 发布阻塞项已修复，或对应功能已默认关闭/隐藏。
- [ ] 当前同步弹窗脏改动已独立验证并明确纳入或排除。
- [ ] `npm run check`、`build`、`privacy`、`ui-contract`、`feature-audit`、provider/chat/security/server 检查通过。
- [ ] Chat、Image、BYOK、Shell/OneAPI、Admin 和移动端重点 E2E 通过。
- [ ] Docker Compose 配置、健康检查、SSE 反向代理提示和回滚路径可执行。
- [ ] 版本号与发布资料更新为 `0.0.7`，提交内容不混入无关脏改动。
- [ ] GitHub 推送、`v0.0.7` 标签和 GHCR 构建结果有真实证据；失败则停止并报告。
