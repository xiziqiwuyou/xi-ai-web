# 图像生成参数精简

## 目标

精简图像生成页的创作参数，只向用户展示模型、尺寸、质量和生成数量，并在不破坏各模型请求格式的前提下，把格式、背景、比例和分辨率转换为内部安全默认值。

## 需求

- 创作参数区只显示模型、尺寸、质量、生成数量四个菜单。
- 尺寸由清晰度和方向组成：`1K`、`2K`、`4K`，每档提供正方形、横版和竖版；默认 `1K 正方形`。
- 模型不支持当前 `2K/4K` 时自动回落为同方向的 `1K`，不得提交模型不支持的 Provider 参数。
- 质量仅提供低、中、高；默认低。
- 生成数量默认 `1 张`，用户仍可在菜单中选择其他可用数量。
- 图片格式固定为 PNG，背景固定为自动，不发送 PNG 无意义的压缩质量。
- 画面比例、Provider 分辨率和像素尺寸继续由尺寸选项内部映射，不能因删除可见菜单而缺失。
- 文生图、图生图、参考图、蒙版、生成耗时统计和结果下载保持可用。
- 桌面四项同排，平板两列，移动端单列，不出现横向溢出。
- 同一行或同一列中的四个参数菜单必须等宽，不因模型菜单内容或列权重产生宽度差异。
- 图像参数菜单统一向上展开，不再根据剩余空间混用上下方向。
- 弹层使用轻微位移和透明度进入动画，避免瞬间出现；遵守系统减少动态效果设置。
- 统一上游只配置域名时，系统必须按厂商自动补全 API 版本前缀：OpenAI、Anthropic 和 OpenAI-Compatible 使用 `/v1`，Gemini 使用 `/v1beta`；后台已经配置版本路径时不得重复添加。
- JSON API 返回 HTML、空响应或无法解析的非 JSON 内容时必须视为上游配置错误，不能把站点首页当成模型输出。
- 提示词优化必须拒绝 HTML 文档和空文本，并向用户返回可执行的错误提示，不得展示或应用异常响应。
- 知识库 Embedding 和 Kimi 联网搜索使用同一托管域名时，必须遵守相同的 `/v1` 端点规则；GLM 的 `/paas/v4/web_search` 厂商路径保持独立。

## 验收标准

- [ ] 页面不存在画面比例、分辨率、背景、输出格式和压缩质量菜单。
- [ ] 默认值为 `1K 正方形`、`低`、PNG 和 `1 张`生成数量。
- [ ] 尺寸菜单按 1K/2K/4K 和正方形/横版/竖版呈现，并按模型能力过滤高分辨率。
- [ ] 请求仍包含正确的 `aspectRatio`、`imageSize`、`size`、`quality`、`outputFormat=png` 和 `background=auto`；PNG 请求不包含 `outputCompression`。
- [ ] 不支持结构化质量字段的模型通过提示词质量语义获得低/中/高偏好，Provider 请求不注入不支持的字段。
- [ ] 四个菜单触发器宽度一致，弹层宽度与各自触发器一致。
- [ ] 模型、尺寸、质量和数量弹层均标记为向上展开，并具有统一进入动画。
- [ ] 裸域名 `https://api.xi-ai.cn` 能分别构造 `/v1/responses`、`/v1/messages`、`/v1/chat/completions` 和 `/v1beta/models/...`；已有 `/v1` 或 `/v1beta` 路径不重复。
- [ ] `200 text/html` 不再进入提示词优化预览，服务端返回明确的 502 上游 API 配置错误。
- [ ] Knowledge Embedding 使用 `/v1/embeddings`，Kimi 搜索使用 `/v1/chat/completions`。
- [ ] TypeScript、UI Contract、图像模块 Playwright、Build、Smoke 和 `git diff --check` 通过。

## 非目标

- 不修改模型目录、后台模型映射或真实请求模型名称；本轮仅修正 Provider API 版本前缀和响应校验。
- 不改变图片编辑、参考图和蒙版上传上限。
- 不重构图像历史、耗时统计、结果区或灵感瀑布流。
- 不新增依赖或全局状态。
