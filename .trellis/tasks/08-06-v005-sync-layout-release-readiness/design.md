# 技术设计

## 1. 版本与任务边界

`v0.0.5` 是当前不可变基线。当前未提交差异只允许落在同步弹窗样式和同步 E2E 回归测试；任何其他路径都必须在审查报告中标记为越界。新版本号、提交、标签和推送属于后续发布动作，不能在本规划文件中宣称已经完成。

## 2. 同步弹窗布局契约

- `.ui-dialog.progress-sync-dialog` 继续使用固定桌面高度，并通过 `calc(100dvh - 32px)` 约束视口。
- 头部和正文使用固定头部加 `minmax(0, 1fr)` 的网格；弹窗本身 `overflow: hidden`。
- `.progress-sync-dialog-body` 是唯一允许承担同步正文纵向滚动的元素，使用稳定 gutter，空闲状态透明滚动条。
- `.progress-sync-section` 和 `.progress-sync-mode` 使用自然高度和顶部对齐，禁止父级 Grid 将内容拉伸到整块视口。
- 状态切换只允许淡入，不使用改变 `getBoundingClientRect()` 的位移动画。
- 审批态继续复用二维码容器，不创建第二个浮层或弹窗。

## 3. 测试契约

几何测试区分“外框稳定性”和“内容自然高度”：弹窗、头部、标签栏、正文视口必须稳定；内容面板的高度可以因状态内容不同而变化，但其横向位置、顶部位置和宽度必须稳定。审批态额外验证正文不溢出、确认按钮可见、审批卡位于二维码区域内且焦点正确。

## 4. 监督智能体

新增 `.codex/agents/xi-ai-web-supervisor.toml`，采用只读工作区权限。该智能体每次被调度时：

1. 读取当前 Trellis 任务、PRD、设计、执行计划和适用规范。
2. 检查 `git status` 与 `git diff`，把未计划路径标记为越界。
3. 检查敏感信息、BYOK/上游域名边界、滚动所有者、错误处理、测试覆盖和发布配置。
4. 运行与变更匹配的最小质量门禁，不修改代码、不提交、不推送、不创建子智能体。
5. 输出 P0-P3 分级发现、证据文件与行号、通过/阻塞结论和下一步建议。

它是可重复调用的监督角色，不声称后台常驻或自动监视服务器；每次开发阶段开始、结束或出现范围变化时由主智能体显式调度。
