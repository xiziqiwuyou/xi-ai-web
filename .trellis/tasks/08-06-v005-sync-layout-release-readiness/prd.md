# v0.0.5 同步布局收口与项目监督基线

## 背景与当前阶段

当前仓库最新发布标签为 `v0.0.5`，对应同步弹窗空闲滚动条隐藏。此前版本主线如下：

- `v0.0.1`: 首个可部署版本基线。
- `v0.0.2`: 发布与 Docker/Compose 部署基线。
- `v0.0.3`: 跨设备同步审批覆盖二维码区域。
- `v0.0.4`: 管理员密码最低长度调整为 8 位。
- `v0.0.5`: 空闲时隐藏同步弹窗滚动条，真实滚动时短暂显示。
- 当前工作区: `v0.0.5` 之后的同步弹窗布局收口改动尚未提交，不能覆盖或修改 `v0.0.5` 标签。

历史任务目录中存在多个仍为 `in_progress` 的旧任务。它们不代表本轮待办；本任务只依据最新 Git 提交、当前工作区差异和本任务验收标准推进。

## 目标

完成跨设备同步弹窗的布局收口，形成可审计、可验证、可发布的下一版本候选基线，并建立一个项目级只读监督智能体，持续检查任务边界、代码质量、测试证据和发布风险。

## 纳入范围

- 同步弹窗正文顶部对齐、标签栏固定高度、内容自然高度布局。
- 桌面同步弹窗固定尺寸和移动端视口安全行为。
- 仅保留一个真实滚动容器；滚动条空闲隐藏、实际滚动后短暂显示。
- 二维码确认、手动授权码、拒绝、取消、超时、加密、API Key 二次确认和接收端恢复协议保持不变。
- 为几何稳定、审批首屏可见、滚动条行为和双向同步流程补充/修正回归测试。
- 运行静态检查、构建、隐私扫描、发布检查和同步专用 E2E。
- 保存版本进度盘点和下一阶段入口，避免历史任务状态造成阶段误判。
- 新增只读 `xi-ai-web-supervisor` 项目监督智能体配置。

## 明确不纳入范围

- 不新增对话、画图、智能体、工作流、知识库或后台业务功能。
- 不修改 OpenAI、Claude、Gemini 或其他厂商请求协议。
- 不增加数据库、Redis、对象存储或新的运行时依赖。
- 不进行真实第三方 API 联调、服务器部署或 GitHub 推送。
- 不清理或批量归档历史 Trellis 任务；历史任务状态单独记录为后续治理事项。
- 不覆盖 `v0.0.5` 标签，不在本任务中伪造线上发布成功状态。

## 验收标准

- [ ] 进入发送、接收、二维码、授权码和审批状态时，桌面弹窗外框、标题、标签栏和正文视口不发生尺寸跳动。
- [ ] 标签栏固定高度，正文内容从标签栏下方开始，不保留由 Grid 拉伸造成的大段顶部空白。
- [ ] 审批确认界面位于二维码区域内，首屏可见且无需向下滚动。
- [ ] 普通状态没有可见右侧滚动条；真实滚动后滚动条短暂出现，随后恢复隐藏。
- [ ] 桌面和移动端始终只有一个同步正文滚动所有者，无水平溢出。
- [ ] 双向二维码、手动授权码、拒绝、确认、取消、超时和恢复流程回归测试通过。
- [ ] `npm run check`、`npm run build`、`npm run privacy`、`npm run release-check`、同步 E2E 和 `git diff --check` 通过。
- [ ] 监督智能体能够读取当前任务、差异、规范和验证命令，并在发现 P0/P1 范围或安全问题时阻止发布建议。

## 后续入口

本任务完成后，下一功能阶段单独创建新任务，优先审查 AI 对话和图片生成的真实上线验收，包括请求失败、流式稳定性、图像字节交付、BYOK 边界、模型目录可用性和部署健康检查。该阶段不得与本同步布局收口任务混写。
