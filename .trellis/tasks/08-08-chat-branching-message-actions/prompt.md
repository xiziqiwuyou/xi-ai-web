# Execution prompt

以 clean-room 方式为 xi-ai-web 增加“聊天消息操作与分支对话”，只借鉴公开的产品行为，不复制 LobeChat 的源码、组件结构、样式、文案、资产、依赖或应用架构。

在现有 React/Vite/Express/IndexedDB 与 BYOK 边界内实现：

1. 为真实持久化消息增加复制、从此分支；用户消息增加编辑并分支；有前序用户消息的助手回复增加在新分支重新生成。
2. 编辑使用消息内联编辑器；确认后创建新分支并通过现有发送管线发送一次。助手重试从对应用户轮次前截断，在新分支重放该用户文本与有效附件，并调用一次现有发送管线。继续分支只创建分支，不请求 API。
3. 原会话和原消息始终不变。新分支使用新 ID、取消置顶、位于列表顶部并展开，其他展开会话自动折叠。
4. 持久化的分支元数据仅包含 parentConversationId、sourceMessageId、mode。不得保存 API Key、URL、待发送附件、Skill/app、联网搜索、知识库、请求状态或通知。编辑/重试所需附件只进入新分支的临时输入状态，并继续接受现有图片能力和数量校验。
5. 流式生成期间禁用会产生竞态的消息操作。自动发送因 Key、模型、能力或上游错误失败时，保留新分支、草稿、附件和可恢复提示。
6. 消息工具使用 Lucide 图标、tooltip、aria-label 和稳定触控目标；桌面 hover/focus 可见，移动端无需 hover；不得改变消息轨道宽度或新增滚动容器。内联编辑支持 Escape、取消、确认和焦点管理。
7. 分支元数据必须经过 IndexedDB、工作区归档和对话归档的 allowlist 清洗。旧数据无迁移成本；非法、超长、残缺或自引用元数据只被丢弃，不能让整个会话失效。
8. 增加纯函数契约、隐私/导入导出契约及桌面/移动端 E2E，证明三种分支模式、原会话不可变、请求只触发一次、流式锁定、键盘和暗黑模式布局。
9. 不增加依赖，不改 Provider 端点，不新增服务端分支 API，不实现分支树/合并/搜索/归档/Artifacts/MCP，不发布版本。

按 P0 合同锁定、P1 持久化、P2 交互执行、P3 浏览器覆盖、P4 全量相关门禁的顺序完成；失败必须修复并重新验证，不得停在半成品。
