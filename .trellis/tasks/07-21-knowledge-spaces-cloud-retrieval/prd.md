# 知识库账号与云端检索

## Goal

在保持 xi-ai-web 其余前台功能无需注册、继续使用用户自带模型 API URL/Key 的前提下，为知识库增加独立身份、跨设备访问、云端文档存储和持久化检索能力。用户只创建一套知识库账号密码；登录后可以创建多个知识库，每个知识库包含自己的文档、Embedding 配置和向量索引。知识库可在知识库问答、AI 对话、智能体与工作流中按授权引用。

## Background

- 当前知识文档保存在浏览器 IndexedDB 的 `knowledgeDocuments` store 中，数据库为 `xi-ai-web-workspace`，见 `src/features/workspace/workspaceDb.ts:15-64`。
- 当前文档包含原文与分块，但不持久化向量；每次知识库问答都会把选中片段上传到服务端并重新嵌入，见 `src/features/knowledge/KnowledgeModule.tsx:240-255`、`server/index.mjs:2598-2615`。
- 普通 AI 对话尚未直接接入云知识库；智能体和工作流通过浏览器文档 ID 与请求内 chunks 使用本地知识，见 `src/features/automation/AutomationModule.tsx:145-154,401-468,981-1018`。
- 主模型和独立联网搜索凭据只存在浏览器 `sessionStorage`。新的知识库身份不得改变这条 BYOK 边界，也不得使知识库账号成为全站账号。

## Requirements

### Identity Boundary

- 全站公共模块继续无需账号；只有知识库页面、知识库选择器及 `/api/kb/*` 接口要求知识库会话。
- 知识库账号密码只用于云知识库，不得自动成为管理员账号、模型 API 凭据或全站用户身份。
- 知识账号使用唯一账号名 + 密码创建，不收集邮箱或手机号；账号恢复依赖一次性恢复码或管理员极端重置。
- 密码只保存强哈希；浏览器使用安全、HttpOnly 的服务端会话，不在 localStorage/sessionStorage 保存明文密码或长期 bearer token。
- 账号名必须经过统一大小写/Unicode 规范化后保持唯一；密码和恢复码使用独立哈希域，不能互相替代。
- 注册成功后恢复码只展示一次，页面必须明确说明其重要性，并提供复制和下载纯文本两种保存方式；用户确认已保存后才能离开完成页。
- 用户使用账号名 + 恢复码重置密码时，必须同时使旧恢复码和全部现有知识库会话失效，并生成一个新的只展示一次的恢复码。
- 登录后允许主动重新生成恢复码；生成后旧恢复码立即失效，并要求再次完成保存确认。
- 如果用户同时遗失密码和恢复码，只能进入管理员极端恢复流程，不能通过公开接口绕过身份验证。
- 登录、注册、会话刷新、退出、限速、失败锁定与恢复流程必须有明确契约。

### Admin Account Operations

- 现有独立 `/admin` 入口增加“知识账号”二级页面，继续受管理员登录保护，前台公共菜单不得出现管理员入口。
- 账号列表支持分页、账号名搜索和状态筛选，显示账号 ID、状态、创建时间、最近登录、活跃会话数、知识库/文档数、`usedBytes`、`reservedBytes`、`quotaBytes` 和失败登录摘要。
- 后台不得返回或展示密码哈希、恢复码哈希、会话令牌、用户 BYOK Key、COS 密钥或文档正文。
- 管理员可以冻结/解冻账号、撤销全部会话、调整容量配额，并发起极端恢复；所有操作必须填写原因并写入不可由普通账号修改的管理员审计日志。
- 极端恢复必须使用 15 分钟有效、单次消费的重置码。服务端只保存重置码哈希；签发时撤销现有会话并使旧恢复码失效，完成重置后用户设置新密码并获得新的恢复码。
- 同一账号同时只能存在一个有效的管理员重置流程；再次签发、成功消费、账号冻结或超时都会使旧重置码失效。
- 管理员只能发起重置，不能读取或还原任何原始秘密。后台文案必须使用“重置账号访问”而不是“查看密码/找回原密码”。
- 后台提供知识账号注册模式设置：关闭注册、仅邀请码、公开注册。模式变化写入管理员审计日志，并通过最小化公开配置让前端显示正确注册状态。
- 后台可以创建、查看状态和撤销邀请码。邀请码明文只在创建成功时展示一次，数据库仅保存哈希、有效期、创建管理员、使用状态和可选的初始容量配额。
- 首版邀请码只能成功消费一次；邀请码消费和知识账号创建必须在同一 PostgreSQL 事务中完成，防止并发重复注册。
- `disabled` 模式只允许已有账号登录；`invite_only` 模式要求有效邀请码；`open` 模式不要求邀请码，但必须启用更严格的 IP/账号名注册限速和自动化滥用防护。
- 后台增加“知识库运行配置”页面，维护新账号默认容量及资源限制。配置保存必须经过服务端 schema 校验、边界裁剪和管理员审计，不能直接接受任意 JSON。
- 账号列表允许对单个账号覆盖总容量、知识库数、文档数、chunk 数和速率限制；未设置的字段继承全局默认值，清除覆盖后重新继承当前全局值。
- 调低限制不得删除既有知识库/文档、回收已用容量或中断运行中任务；账号超出新限制后进入“只读新增受限”状态，现有内容仍可读取和删除，直至用量回落。
- 调低并发上限不终止已开始任务；新的上传或解析任务排队。调低 `maxTopK` 后所有新请求由服务端按新值裁剪。

### Default Resource Limits

- `defaultQuotaBytes`: 5 GiB（`5 * 1024 * 1024 * 1024`）。
- `maxKnowledgeBasesPerAccount`: 20。
- `maxDocumentsPerAccount`: 1,000。
- `maxDocumentsPerKnowledgeBase`: 500。
- `maxFileBytes`: 100 MiB（`100 * 1024 * 1024`）。
- `maxChunksPerAccount`: 100,000 个有效 chunks。
- `maxConcurrentUploadsPerAccount`: 3。
- `maxConcurrentIngestionsPerAccount`: 2。
- `retrievalRequestsPerMinutePerAccount`: 60。
- `maxRetrievalTopK`: 20。
- 所有限制均由服务端执行，前端只负责提前提示；客户端修改、遗漏或伪造限制参数不能绕过后端校验。

### Knowledge Bases And Access

- 登录后可以创建、重命名、归档和删除多个知识库；知识库负责组织文档、Embedding 配置、索引版本和检索设置。
- 文档、分块、向量和检索请求必须始终带有服务端验证的 account/knowledge-base 边界，禁止依赖客户端传来的 owner ID 做授权。
- Embedding 模型与索引版本归属知识库，允许同一账号的不同知识库选择不同的 OpenAI/Qwen Embedding 模型。
- 首版不创建成员关系、邀请链接、公开分享或协作角色；任一有效账号会话拥有该账号全部知识库权限。
- 同一账号允许多端并发会话。审计记录必须包含账号 ID、会话 ID、时间和操作，但不声称能够识别共用账号背后的具体个人。
- 新设备凭知识账号凭据应能恢复知识库、文档列表和处理状态；配置与目标知识库索引兼容的 BYOK Embedding 连接后恢复语义检索能力。浏览器 IndexedDB 只作为可选缓存，不再是云知识库事实来源。

### Documents And Retrieval

- 原文件直接上传至 COS 或兼容 S3 的对象存储，应用服务器不长期保存上传文件。
- 浏览器只能获取限定到单个账号/知识库/对象路径、短时有效的上传授权，不能获得 COS 永久密钥。
- 服务端维护文档元数据、处理状态、解析版本、分块版本、embedding 模型与维度。
- 文档处理必须支持可重试、幂等和可观察的状态：`uploaded -> parsing -> embedding -> ready | failed`。
- 文档状态至少覆盖 `uploaded`、`parsing`、`awaiting_embedding`、`embedding`、`ready`、`needs_ocr`、`failed` 和 `deleting`。只有 `ready` 文档可以参与检索。
- PostgreSQL 保存账号、会话、知识库、文档元数据、处理任务、chunks 和 pgvector 向量；COS 保存原文件及可选的标准化解析文本，应用服务器不长期保存上传内容。
- 每个知识库必须持久化 `embeddingVendor`、模型目录 ID、实际请求模型名、向量维度和索引/分块版本，但不得保存用户 API URL/Key。
- 首版允许从公开模型目录选择 OpenAI 与 Qwen embedding 模型。索引和查询必须使用兼容的厂商、实际模型名与向量维度。
- 修改知识库的 embedding 模型不能原地混用旧向量，必须创建新的索引版本并重新向量化，成功切换后再清理旧版本。
- 当用户未提供兼容的 BYOK Embedding 连接时，可以登录、查看知识库和文档状态，但不能上传后完成向量化、重新索引或执行语义检索；UI 必须明确要求配置连接。
- 向量检索层仍通过适配器隔离，使 pgvector 的表结构和调用逻辑不泄漏到前端契约，并为未来迁移托管向量数据库保留边界。
- 删除知识库或文档必须清理对象、向量及元数据，失败时进入可重试清理队列，不能只删除 UI 记录。
- 文件类型必须通过扩展名、声明 MIME 和内容签名联合校验，不能只信任浏览器传入的文件名或 MIME。
- PDF、DOCX、XLSX 和 PPTX 使用成熟解析库提取文本与结构；TXT/Markdown/CSV/JSON/HTML 使用受限解析器。Office 压缩包必须设置解压大小、文件数量和嵌套层级限制，防止压缩炸弹。
- 解析结果必须保留可引用的来源定位：PDF 页码、DOCX 标题/段落、XLSX 工作表与单元格范围、PPTX 幻灯片号、HTML 标题/段落以及纯文本行范围。
- HTML 只提取文本与允许的结构信息，不执行脚本、不加载远程资源，也不保留可执行内容。
- 扫描 PDF、图片文件或其他无法提取有效文本的内容标记为 `needs_ocr`，不生成 chunks 和向量，不消耗向量 payload 配额；原文件仍计入 COS 总容量。
- 首版不提供 OCR 服务凭据或自动 OCR 请求。数据模型和任务状态保留 OCR 适配入口，后续可由管理员配置腾讯云 OCR 或其他服务。
- COS 上传完成后，后台解析任务独立于浏览器会话执行并持久化 chunks；解析完成进入 `awaiting_embedding`，不得把“上传成功”显示成“已可检索”。
- 向量化由前端在用户在线时触发可重入批次请求。每批由服务端原子领取未完成 chunks、临时调用对应 BYOK Embedding API、写入向量并提交进度；API Key 只存在该请求内。
- 页面关闭、网络中断、Key 失效或服务重启不得丢失已完成向量。未完成批次回到可重试状态，文档保持 `awaiting_embedding` 或显示可恢复错误。
- 同一文档/索引版本不能被两个会话重复向量化同一批 chunks；服务端使用批次租约、幂等键和唯一约束防止重复计费与向量覆盖。
- 用户重新登录后，知识库列表需要聚合显示未完成索引数量，并提供“继续索引”入口；用户重新配置兼容 URL/Key 后从第一个未完成批次继续。
- 上传前、开始向量化前和用户尝试离开存在活跃批次的页面时均要说明：解析可继续，向量化会暂停且稍后可恢复。提示不得暗示服务端会保存 Key。

### AI Integration

- 知识库问答必须由服务端按当前会话和知识库归属检索，不能再由浏览器上传整个知识库 chunks。
- AI 对话增加知识库/文档选择器；请求只发送授权资源 ID，服务端检索后注入带来源、受长度限制的上下文。
- 智能体和工作流由本地 `knowledgeDocumentIds` 迁移为可解析的知识资源引用，并在运行时重新校验权限。
- 回答必须返回引用信息，至少包含知识库、文档、chunk/source locator 和可安全打开的短时下载地址。
- 主模型仍使用用户当前 BYOK 连接；知识库服务不得持久化用户的主模型 API Key。
- AI 对话、知识库问答、智能体和工作流单次最多引用 3 个知识库。客户端提交知识库 ID，服务端验证全部知识库归属当前知识账号。
- 服务端按 `embeddingVendor + actualModel + dimensions + indexVersion` 对所选知识库分组；每个 Embedding profile 只生成一次查询向量，再分别按知识库过滤检索。
- 不同 Embedding profile 的检索结果采用确定性的归一化/融合策略合并，最终注入主模型的片段总数不得超过后台 `maxRetrievalTopK`（默认 20），每条引用保留知识库和文档来源。
- 浏览器会话维护独立于主模型连接的知识 Embedding 连接集合，至少支持 OpenAI 和 Qwen。连接可以在兼容时复用当前主模型 BYOK 配置，否则要求用户单独填写对应 URL/Key。
- 知识 Embedding URL/Key 只保存在浏览器 `sessionStorage`，不进入 PostgreSQL、COS、工作区导出、日志或公共 bootstrap；仅在索引/检索确实需要对应 profile 时随请求发送。
- 任一已选知识库缺少兼容连接、索引未就绪或权限校验失败时，必须在调用主模型前整体失败并指出具体知识库，不能静默跳过或返回不完整知识结果。

### Operations And Privacy

- 服务端必须对每个账号实施默认 5 GiB 总知识库容量配额。计费逻辑字节包括 COS 原文件、COS 中单独保存的标准化解析文本、PostgreSQL chunk 文本和 pgvector 向量 payload；关系元数据和数据库索引内部开销不计入用户额度。
- 账号容量至少维护 `quotaBytes`、`usedBytes` 和 `reservedBytes`。上传授权、解析、向量化和重新索引必须在 PostgreSQL 事务中先预留容量，完成后按实际逻辑字节结算，失败或取消后释放预留。
- COS 上传完成后必须通过服务端校验对象实际大小和归属，不能信任浏览器声明的文件大小。过期或中断的容量预留需要由定时清理任务释放。
- 删除文档或知识库只有在对象、chunks 和向量进入可靠删除流程后才回收额度；部分删除失败必须保留可重试清理记录，不能先减少 `usedBytes` 再遗留数据。
- 重新索引期间旧索引继续可读，新索引占用需要完整预留；账号剩余容量不足以同时容纳新旧版本时阻止重建并提示先清理内容。
- 另行设置每账号的知识库数、文档数、单文件大小、chunk 数、检索速率和向量化并发限制，避免知识账号注册和共享凭据被滥用。
- 对注册、登录、上传授权、删除和检索记录审计事件，但日志不得包含密码、会话令牌、COS/向量库密钥或完整文档正文。
- 服务端备份必须覆盖知识账号元数据和关系数据；COS 使用版本控制/生命周期策略；向量索引必须可由原文件和元数据重建。
- 现有本地知识文档提供显式“迁移到云知识库”流程，不在用户不知情时自动上传。

## Acceptance Criteria

- [ ] 未登录用户仍可使用非知识库模块；进入知识库或调用 `/api/kb/*` 时只触发知识库登录。
- [ ] 一个知识账号可以创建多个知识库；任何资源查询均由服务端验证 `account -> knowledge base -> document/chunk` 完整归属链。
- [ ] 知识库没有成员、邀请、公开分享或协作接口；同一账号的多端会话可以访问相同知识库，并留下会话级审计记录。
- [ ] 用户在设备 A 创建知识库并上传文档后，在设备 B 登录同一知识账号可以看到相同内容；配置兼容的 OpenAI/Qwen Embedding BYOK 连接后可以检索。
- [ ] 密码、会话、COS 密钥、向量数据库密钥和用户 BYOK 模型密钥均遵守各自独立的存储与传输边界。
- [ ] 注册完成页强提醒恢复码的重要性，支持复制/下载并要求保存确认；后续任何页面和 API 都无法再次读取原恢复码。
- [ ] 用户恢复和管理员极端恢复都会撤销全部旧会话、废弃旧恢复码并生成新的单次展示恢复码；管理员重置码 15 分钟过期、只能消费一次且数据库只保存哈希。
- [ ] `/admin` 的知识账号列表支持检索、状态、容量与会话管理，但任何响应和页面均不包含密码/恢复码哈希、令牌、BYOK Key 或文档正文。
- [ ] 冻结、解冻、配额调整、会话撤销和极端恢复均记录管理员、目标账号、原因、时间和结果。
- [ ] 管理员可在关闭注册、仅邀请码和公开注册之间切换；默认仅邀请码，前台不会在关闭注册时提交无效注册请求。
- [ ] 邀请码只展示一次、数据库只存哈希、可撤销/过期，并在账号创建事务中最多消费一次。
- [ ] 公开注册仍受服务端注册限速和滥用防护约束，切换模式不会影响已有账号登录。
- [ ] 后台可配置所有首版默认资源限制，并能为单个账号设置/清除覆盖值；配置变更经过校验且写入审计日志。
- [ ] 调低限制不会删除已有数据或中断任务；超限账号仍能读取和删除内容，但不能继续增加受限资源。
- [ ] 前端伪造配额、文件大小、并发数、topK 或速率参数均无法绕过服务端限制。
- [ ] 上传文件不经过应用服务器长期落盘，且前端授权只允许访问当前账号知识库下的目标对象。
- [ ] 检索始终按服务端授权的知识库过滤，并返回可追踪引用；跨账号或跨知识库资源 ID 无法越权读取。
- [ ] AI 对话、知识库问答、智能体和工作流使用同一套服务端检索契约。
- [ ] 单次最多选择 3 个知识库；服务端校验完整归属、按 Embedding profile 分组检索并融合为最多 20 个可追踪引用。
- [ ] 任一知识库缺少兼容 BYOK Embedding 连接或索引未就绪时，请求在主模型调用前失败且不产生部分回答。
- [ ] OpenAI/Qwen 知识 Embedding 连接只存在浏览器会话并按需发送，不进入数据库、COS、导出、日志或公共配置。
- [ ] 服务端只持久化 embedding 厂商、模型目录 ID、实际模型名、维度和索引版本，数据库、日志、COS 对象和导出文件均不包含用户 Embedding API URL/Key。
- [ ] 切换 embedding 模型通过可回滚的重建流程产生新索引版本，旧向量与新向量不会混用。
- [ ] 默认 5 GiB 总容量按规定的逻辑字节口径由服务端原子预留与结算；并发上传、失败任务、删除和重新索引不会绕过配额或永久占用预留空间。
- [ ] COS 实际对象大小、chunk UTF-8 字节和向量 payload 字节均可重算，定期对账能够发现并修正额度漂移。
- [ ] 支持 PDF、DOCX、XLSX、PPTX、TXT、Markdown、CSV、JSON 和 HTML，并通过真实内容校验拒绝伪造或不支持的文件。
- [ ] 文档引用可以定位到页码、段落、工作表/单元格、幻灯片或行范围；HTML 和 Office 文档解析不执行任何嵌入代码或远程资源。
- [ ] 无可提取文本的扫描 PDF/图片进入 `needs_ocr`，不产生 chunks/向量；后台和前台明确显示首版未配置 OCR。
- [ ] 文档解析可在用户离线后继续，解析完成进入 `awaiting_embedding`；只有用户在线携带兼容 Key 时才按幂等批次生成向量。
- [ ] 关闭页面、断网、Key 失效和服务重启后，已完成批次不重复，未完成进度可从知识库列表恢复。
- [ ] 上传、等待 Key、向量化和可检索状态有明确提示，任何界面都不会把尚未 `ready` 的文档表示为可用于 AI 检索。
- [ ] 本地知识文档只有在用户主动确认后才迁移到云知识库，迁移失败不会破坏原 IndexedDB 数据。
- [ ] 对象存储、关系元数据与向量索引均有备份、重建、配额、审计和失败恢复验证。

## Out Of Scope For MVP

- 将知识库账号扩展为全站账号。
- 在浏览器保存腾讯云永久 SecretId/SecretKey 或向量数据库 root key。
- 成员邀请、角色权限、公开分享、实时多人协作、知识库市场和组织级计费。
- 将处于内测状态的 COS 文档向量检索作为唯一不可替换的生产依赖。
